Explore a fleet with the CLI

The CLI is a separate way to inspect Paprika. Its release installer checks the downloaded archive. The example login below connects to the project’s hosted API; a self-hosted installation uses your own server address.

install.sh verified release archive
Latest published release curl -fsSL https://raw.githubusercontent.com/paprikacd/paprika/master/install.sh | sh
Pin a release curl -fsSL https://raw.githubusercontent.com/paprikacd/paprika/master/install.sh | PAPRIKA_VERSION=vX.Y.Z sh
Choose a writable destination curl -fsSL https://raw.githubusercontent.com/paprikacd/paprika/master/install.sh | PAPRIKA_INSTALL_DIR="$HOME/.local/bin" sh

Copy unavailable? Select the command text and copy it manually.

Platform and integrity

Supports Darwin (macOS) and Linux on amd64 and arm64. The installer downloads over HTTPS and verifies the selected archive against the release checksum before replacing the binary.

Version and checksum

Set PAPRIKA_VERSION=vX.Y.Z for a reproducible install. Audit the latest published checksums. A pinned release uses https://github.com/paprikacd/paprika/releases/download/vX.Y.Z/checksums.txt.

No implicit privilege escalation

The script never invokes sudo. Set PAPRIKA_INSTALL_DIR to any writable directory; if it falls back to ~/.local/bin, it prints the exact PATH export to add. A Homebrew formula is not yet supported.

Build from source

Prefer to inspect and compile the CLI yourself? Clone the canonical repository and build the CLI with the pinned Go toolchain.

git clone https://github.com/paprikacd/paprika.git
cd paprika
go build -o ./bin/paprika ./cmd/paprika

Why Paprika

Core pieces of Application Delivery

The project combines these capabilities in Kubernetes resources. Start with a release path, then add the controls you need.

Application CRD

Unified Resource Model

Define a source and stages in an Application resource. Paprika creates and tracks the related release resources.

Canary steps

Progressive Delivery

Configure canary steps and verification checks for staged rollouts. Rollback behavior depends on the selected strategy and checks.

Istio + Gateway API

Pluggable Traffic Routing

Built-in support for Istio VirtualServices and Gateway API HTTPRoutes. Per-stage traffic router configuration gives you fine-grained control over how traffic reaches your canaries.

Cluster references

Multi-Cluster by Default

Target a registered cluster from a stage. Review the multi-cluster guide for credentials, setup, and supported modes.

Verify before promote

CEL Health Verification

Use built-in resource health assessment and optional CEL checks to control promotion. Add manual approval gates where people need to review a release.

Live via SSE

Real-time Dashboard

Inspect applications, pipelines, releases, and resources in the dashboard. The API also provides programmatic access to fleet state.

How It Works

From Source to Production in Three Steps

Define, promote, verify — Paprika handles rendering, traffic routing, and health checking so you don't have to.

Step 1

Define Your Application

Create an Application that names its source, stages, and release strategy. The getting started guide includes a complete manifest.

Step 2

Promote Through Stages

Paprika renders the source and creates a release. Pipeline steps can run as Kubernetes Jobs; stages can target registered clusters.

Step 3

Verify and Release

Inspect resource health and release status as each stage progresses. Add canary traffic routing or manual gates when the application needs them.

Where it fits
