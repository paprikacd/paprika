## Diagnose the actual bottleneck

Count examples, registered renderer identities, routes and portable saved compositions separately. An impressive gallery does not automatically establish easy authoring or complete dashboard generation.

The 2026-10-31 Widget Lab expansion demonstrated profiling, cohorts, scientific/spatial fields, planning and multivariate exploration. Review also found repeated panel/inspection owners, metadata split across lists, config validation without actual field-binding validation, and linked state in React rather than the saved document. Treat these as dated lab observations, not permanent claims about upstream Paprika.

Inspect current owners and actual captures before extending the system. Identify the dominant problem: missing family, wrong semantics, visual drift, interaction ownership, discovery or portability. Prefer one complete vertical slice when shared infrastructure is the bottleneck.

## Consolidate repeated responsibilities

When a fix recurs across families, choose one maintained owner or declarative capability:

| Repeated work | Shared responsibility |
| --- | --- |
| Title/actions, disclosure, Edit and panel spacing | Panel frame with plot/legend/detail slots |
| Font roles, surface/grid/selection colors and durations | Thin chart-token adapter over Gamma/Insights |
| Hover/focus/pin, Escape, focus return, stale selection | Shared inspection lifecycle with chart-specific content |
| Natural/fill height, useful sizes and overflow | Registry layout metadata used by host/editor/catalogue |
| Applied overrides and controlled selection | Host state owner with explicit replacement rules |
| Fields, eligibility, diagnostics and config controls | Registry contract plus semantic adapter |
| Routes, labels, icons, search and lazy loader | Trusted lens manifest; derive navigation and counts |
| Fixture states, examples and capability descriptions | Evaluation manifest linked to registered owners |

Keep numerical algorithms and genuinely different gestures family-owned. Avoid a huge component with unrelated flags. Reuse the registry, query scheduler, normalized results and existing dashboard schema.

## Preserve reference quality

Compare equal-size captures and reading relationships: useful plot area, hierarchy, row pitch, aligned plot bounds, exact values and selected-state composition. Shared dark colors alone do not establish fidelity.

- Apply shared panel/value/unit/axis/legend/detail/identifier roles. Retain the product's readable floor for essential labels. Reduce ticks or secondary prose before shrinking type.
- Consume structural theme tokens. Keep categorical identity, magnitude, severity and selection distinct. Preserve authored overrides explicitly; one dark capture does not verify alternate themes.
- Budget shell, scope controls, title, plot, legend and inspection separately. Avoid metadata bands or fixed KPI counts that push the decision signal below the first useful viewport.
- Position inspectors against actual panel/viewport bounds. Use anchored transient, pinned, docked or inline presentation according to space; do not hide the selected mark or required comparison behind a fixed overlay.
- Distinguish intentional scrolling for wide tables/matrices/schedules from accidental overflow in ordinary 2D plots. Page-width equality does not prove useful inner layout.
- Let the lens declare which selection controls it owns. Retain standalone controls in the library while removing identical duplicates from composed panels.
- Keep direct manipulation immediate. Share short selection/surface transitions and interruptible domain transitions where meaningful. Preserve exact values and settled history. Reduced motion changes effects, not meaning.

Keep all destinations discoverable while allowing a compact investigation shell. A grouped searchable picker and an all-lenses view can reduce permanent header height. Verify direct routes, search, desktop navigation and narrow controls so new lenses cannot disappear.

## Run a real-host preflight

Before scaling a new family or lens:

1. Pass the complete fixture through the canonical result parser, including byte/row/column limits.
2. Parse Widget/config through the registered owner.
3. Run the pure semantic adapter against the proposed binding; check units, identity, population and accounting.
4. Mount through the actual chart/editor host and containment, not only an isolated SVG.
5. Exercise an actual native input submission, selection/pin/dismiss, narrow layout and reset.
6. Declare effective transport, adapter and render budgets together. Do not silently truncate observations or advertise the largest private parser bound as UI capacity.

Keep checks bounded and targeted. Add tests for substantive numerical/interaction risks; do not mirror CSS or repeatedly rerun unrelated checks after sufficient evidence.

## Build one complete authoring slice

Start discovery/generation changes with contrasting existing families. Raw-sample distributions test role mapping and related visual alternatives; aggregate/chronological profiles test semantic incompatibility despite shared primitive types; maps test coordinate roles and independent camera/selection.

Deliver discovery → mapping → preview → invalid-input recovery → canonical generation → export/reopen, including supported inspection and linked state. Keep unavailable host capabilities explicit. Use [schema discovery and generation](schema-discovery-and-generation.md) for the detailed contract; expand incrementally after the slice proves useful.

## Make evaluation repeatable

Keep a small benchmark set: original Edge/Reliability anchors, a dense profile, spatial field and multivariate composition. Pair each with deterministic fixture revision, source mode, exact canvas/theme, selected state and expected interaction. Do not fabricate an initial observation merely for visual polish.

Generate review packets from declared examples when tooling permits: canonical validation, named semantic checks, actual browser actions, selected/degraded captures and measured performance. Visual judgment remains separate from screenshot existence. Compare the same data and state; review intended differences rather than rejecting every pixel change automatically.

Keep analytical truth, readable hierarchy, interaction, accessibility, authorability/portability and measured performance as separate gates, with unverified/not-applicable states. Unit success does not establish reference fidelity; a narrow container preview does not establish physical-device/focus-path coverage.

Measure progress through fewer manual registration points, invalid bindings caught before rendering, generated documents reopened without repair, fewer unrelated regeneration edits, and less repeated visual correction. Establish baselines before inventing improvement targets.
