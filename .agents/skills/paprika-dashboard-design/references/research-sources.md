# Research source map

Research date: **2026-10-30**. This skill is an original synthesis of the primary sources below. It does not bundle their code, illustrations or substantial prose. Public `main` and `latest` links are mutable; recheck the relevant source before changing an implementation. Paprika links are pinned to the inspected revision.

## How to interpret the evidence

- **Standards:** WCAG success criteria provide testable accessibility requirements when claiming the relevant conformance level. Its tutorials explain possible implementations; they are not additional success criteria.
- **Provider and repository contracts:** Prometheus semantics and verified Paprika contracts constrain data handling. Existing code is evidence of shipped behavior, not proof that every behavior is desirable or correct.
- **Design guidance and research:** Grafana, ONS, Google SRE and the visualization paper inform decisions within their stated scope.
- **Craft references:** The design references inform the workflow and visual judgment. Their illustration or marketing conventions do not override analytical correctness. Mebius preview images establish appearance; its public implementation modules establish code paths, not measured browser performance or accessibility.
- **Framework evidence:** Versioned source and exports establish available APIs. They do not establish that Paprika has integrated those APIs, that every renderer behaves identically, or that a representative dashboard has been benchmarked.
- **Paprika defaults:** This skill's review rubric, fixture matrix, suggested density, series limits, typography, animation timing and performance budgets are project choices unless explicitly tied to a maintained contract. They are not universal research findings. Record exceptions with the task and evidence.

## Chart semantics, accessibility and operational practice

| Primary source | Application in this skill | Limit of the evidence |
| --- | --- | --- |
| [Prometheus query functions](https://prometheus.io/docs/prometheus/latest/querying/functions/) | Respect counter reset handling, compute rates before cross-series aggregation, and retain function-specific missing/mixed-sample behavior. | Verify the deployed Prometheus version and provider capabilities. A syntactically plausible query does not establish correct metric semantics. |
| [Prometheus histograms and summaries](https://prometheus.io/docs/practices/histograms/) | Distinguish bucket distributions from precomputed summary quantiles; aggregate compatible distributions before estimating a fleet quantile. | Averaging per-instance p99 values does not produce the fleet p99. Native and classic histogram support must be verified separately. |
| [Grafana dashboard best practices](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/) | Use explicit observability questions, meaningful grouping, comparable scales and deliberate drilldown. | RED, USE and golden signals are useful task frameworks, not mandatory panel templates for every dashboard. This source does not establish Paprika feature parity. |
| [Grafana query and transform data](https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/query-transform-data/) | Make query, resolution and transformation decisions inspectable; distinguish retrieval from presentation. | Grafana's options and current preview features are not automatically Paprika capabilities. |
| [ONS axes and gridlines](https://service-manual.ons.gov.uk/data-visualisation/guidance/axes-and-gridlines) | Preserve zero baselines for magnitude encoded by bars/filled areas; use deliberate domains for lines and scatter; keep reference geometry subordinate to data. | This is not a rule that every line chart must start at zero. ONS styling values are not Paprika tokens. |
| [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/) | Check non-text alternatives, color independence, text/non-text contrast, keyboard operation, focus, pointer alternatives and applicable target-size criteria. | Automated checks or declared compliance fields do not establish conformance. Apply each criterion's scope and exceptions accurately. |
| [W3C WAI complex images tutorial](https://www.w3.org/WAI/tutorials/images/complex/) | Provide an identifying description plus access to the essential relationships, trends and values represented by a complex chart. | A filename or generic `aria-label` is insufficient. A data table helps convey exact values but may still need a summary of the visual relationships. |
| [Google SRE: Implementing SLOs](https://sre.google/workbook/implementing-slos/) and [Alerting on SLOs](https://sre.google/workbook/alerting-on-slos/) | Tie reliability views to user-facing SLIs, explicit objectives/windows and error-budget interpretation; distinguish observation from alert evaluation. | Targets, burn-rate windows and paging policy depend on the service. Do not invent them from a chart's red threshold or transplant example thresholds universally. |
| [MinMaxLTTB: Leveraging MinMax-Preselection to Scale LTTB](https://arxiv.org/abs/2305.00332), Van Der Donckt et al., 2023 | Consider computational cost and visual representativeness when selecting display samples. The paper evaluates a MinMax preselection followed by LTTB. | It does **not** establish a guarantee that every extremum survives the final selection. An extrema-preserving envelope requires a separate explicit contract. Display sampling must not become the input to exact statistics or alerts. |
