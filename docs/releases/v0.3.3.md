# Paprika v0.3.3

Promotion verification can recover from a failed candidate through an explicit,
release-bound retry. A fresh retry attempt creates a new verification Pipeline
and Jobs, invalidates previous verification and approval, and checks current
upstream identity and health before admission. Manual sync continues to repair
only the accepted deployment.

Retrying a failed Pipeline step now resumes execution, preserves successful
prerequisites, and resets affected downstream steps and attempt budgets. An
interrupted upstream health observation restarts the promotion duration window,
including candidates waiting for a sync window.

Workload health waits for the controller to observe the applied generation.
Deployment health also waits for old replicas to leave, and DaemonSet health
requires updated, available pods. ReplicaSet health uses its supported counters.
These checks prevent sync waves from advancing on healthy counts belonging to
the previous rollout.

HTTP smoke gates refuse redirects so another environment cannot satisfy the
configured endpoint's reachability check. Applications requiring response-body,
build-identity, or authentication assertions should use semantic health checks
and verification Jobs.

The retry annotation and operational examples are documented in the
[environment promotion guide](../guides/environment-promotion.md).
