## Five stages
### 1. Establish the baseline
Freeze and identify source: commit plus relevant working-tree hash; preserve concurrent work. Inventory actual images, concepts, sample source and missing remote/reference evidence. Record screenshot paths, theme, route, viewport method and sample state. Inspect pixels before tests or lint decide the narrative.
### 2. Independent whole-journey critique
Review opening canvas, data selection, authoring and return as one experience. Each lens names actual defects and what should remain. Prioritize at most three coherent issues per batch. P1 means material difficulty/confusion or displacement of the primary work, even when functional tests pass. No invented measurements or numerical aesthetic scores.
### 3. Fix the prioritized batch
Implementation owner fixes shared causes, not screenshot-specific symptoms. Preserve queries, exact selected time/value, saved placement, history and save boundaries. Add regressions at affected width/count/state boundaries. Do not lower tests or hide document overflow to manufacture acceptance.
### 4. Fresh confirmation
Capture the changed states on the frozen candidate. Compare actual before/after whole screens plus relevant details. Check both what improved and whether something formerly better regressed. If a major defect remains, do not approve: return a bounded corrective batch and recheck the affected states. Stop optional style polishing after major criteria are met; record genuine remaining limitations.
### 5. Explicit decision and receipt
Separate **composition** and **functional** verdicts. Functional tests support behavior, not beauty. A record validator establishes evidence completeness, not aesthetic certification. Name independent artistic/source reviewers accurately; never invent another agent. Package only after required major corrections and candidate-bound evidence; deployment/live integration needs its own actual receipt.

## Minimum state/evidence matrix for this slice
| Surface | Evidence required |
|---|---|
| Whole overview | Desktop light/dark; tablet; 390px mobile; normal and compact where supported; real plot/legend/stat geometry and page width measurements |
| Responsive stat projection | Counts 1–8/source boundaries including 839/840/841 where applicable; no orphan holes, no lost widgets, saved coordinates unchanged; source tests plus representative actual pixels |
| Mobile actions | Open named menu, Manage/AI reachable, visible Edit/Save, keyboard selection/Escape/focus return, 44px targets where measured |
| Editor | Narrow view and widget settings; all five tabs readable/reachable at 320/390px; title/query fields/actions remain usable; no accidental changed save model |
| Observation | Pin exact value/time; keyboard/touch-accessible details; dismiss and return; refresh stale selection contract tested or explicitly unverified |
| Local persistence | Edit→Save→reload→restore original sample state; distinguish browser-local storage from authenticated service persistence |
| Empty/error/recovery | Exercise safely supported sample states or label not browser-tested; never reuse historical backend tests as fresh live UI evidence |

Use one coordinated CUA owner. Iframe widths are app-frame viewports, not device emulation. No separate-browser inspectors or unsupported viewport APIs. Screenshot filename alone is not provenance: bind captures to actual source/time/state; mark older captures precisely when later deltas occur. Screenshots used to approve a state must actually be opened and inspected, including dirty/footer/action states.
