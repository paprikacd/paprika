# Paprika feature design catalogue

**Paprika Working System v1** aligns 29 feature designs around one visual language and links them to 30 existing implementation issues. Every feature has a canonical artboard, an editable specification, an exact synthetic fixture and its original acceptance criteria. The designs are proposed product work; publishing the catalogue does not mark the features implemented.

[Shared design system](design-system.md) · [Machine-readable catalogue](manifest.json) · [Generation prompts](generation-prompts.json) · [Exploration archive](explorations/README.md) · [Space catalogue](https://chatgpt.com/space/page_33e4ede12ad88191af7ba4843bc74534) · [Working System in Space](https://chatgpt.com/space/page_83d1294312088191bf8b0b831d680eb2)

## How to use the catalogue

Start with the shared shell, type, spacing and state roles, then read the feature's own working-surface and interaction contract. The native fixture and linked backlog criteria define behavior. Artwork illustrates layout and hierarchy. Existing implementation foundations are identified separately from proposed additions.

Timelines, ledgers, matrices, comparisons, forms and selected inspectors retain their purpose inside the shared visual family. The archive retains all 44 reviewed exploratory PNGs alongside the 29 canonical artboards. The six earlier promotion directions remain linked through the existing Space gallery.

## Scope and ownership

The catalogue references `paprikacd/paprika` at [17a651ab](https://github.com/paprikacd/paprika/tree/17a651ab8edf20337ac5319af93ae7fb2c389b47) and implementation issue bodies read on 2026-11-11. All 30 referenced implementation issues were open at that read. PR #238 is implementation work for the query inspector and is not another feature issue.

Imported profile comparison and authorized production profile sourcing remain two separate implementation issues behind one design surface. Related issues and reusable foundations are linked in each feature specification; the catalogue creates no duplicate backlog.

Runtime integration uses the existing main-console tokens and fonts, scoped Gamma adapter, canonical controls and execution/data owners. The catalogue introduces no competing runtime theme, schema, scheduler or execution engine.

## Design and implementation status

The shared design direction and the implementation backlog are separate records. Review and publish the design package through its documentation PR. Keep implementation issues open until their own behavior, authorization, data and verification criteria are met. Documentation or image publication is not a deployment receipt.
