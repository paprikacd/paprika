# Extending `proto/paprika/v1/api.proto` safely — conventions, regeneration, and guardrails

Scope: everything an implementer needs to add messages/enums/RPCs for the console
redesign without breaking the build, CI, or the existing descriptor contract tests.

Repo root referenced throughout: `/Users/benebsworth/projects/paprika`

---

## 0. TL;DR — the five rules that will bite you

1. **`internal/api/fleet_contract_test.go` sha256-locks 120 existing messages.**
   Adding *any* field to `Application`, `Rollout`, `Release`, `Pipeline`,
   `GetResourceResponse`, `ResourceSync`, `ResourceTreeNode`, `ArtifactRef`, … changes
   the hash and fails `TestFleetDescriptor`. Prefer **new sibling messages + new RPCs**.
   If you must extend a locked message, recompute the hash (recipe in §6.1).
2. **New RPCs must be appended at the END of `service PaprikaService`** (index ≥ 41).
   The contract test walks `methods.Get(i)` by *positional index* for indices 0–39.
3. **`PaprikaServer` does NOT embed `UnimplementedPaprikaServiceHandler`.** Adding an
   RPC to the proto immediately breaks the compile of `internal/api/server.go:201`
   (`var _ v1connect.PaprikaServiceHandler = (*PaprikaServer)(nil)`). You must
   implement the method on `*PaprikaServer` in the same change.
4. **Adding a value to any `Fleet*` enum fails `TestFleetDescriptor`** — the enum maps
   are compared with exact `require.Equalf`. Update the map in the test.
5. **Generated code is committed and CI verifies zero drift** (`generated` job wipes
   `internal/api/paprika` + `ui/src/gen`, regenerates, and requires a clean tree).
   Always run `make generate-proto` and commit the output.

## 5. Proto style conventions in `api.proto`

### 5.1 File header
```proto
syntax = "proto3";

package paprika.v1;

option go_package = "github.com/benebsworth/paprika/internal/api/paprika/v1";
```
No imports at all — **no `google/protobuf/timestamp.proto`, no wrappers, no
protovalidate.** Timestamps are scalars (see 5.5). Keep it that way unless you also add
a `deps:` entry, which would require BSR network access in CI.

### 5.2 Ordering / layout
- Domain/value messages first, then Request/Response pairs grouped per feature area, then
  the newest "fleet" enums + messages, then `service PaprikaService` **last** (line 1145).
- Request/Response are declared adjacent, `XRequest` immediately before `XResponse`.
- Blank line between top-level declarations; 2-space indent; `{` on the same line.
- Trivial responses may be one-lined: `message GetPipelineResponse { Pipeline pipeline = 1; }`
  (line 640), `message GetStepLogsResponse { string logs = 1; }` (line 685).
- Empty messages: `message RetryStepResponse {}` (line 664), `message SkipStepResponse {}`,
  `message CancelPipelineResponse {}`, `message ListInvestigatorPluginsRequest {}`.

### 5.3 Naming
- Messages/enums: `UpperCamelCase`. Fields: `lower_snake_case`.
- RPCs: `UpperCamelCase`, verb-first. Existing verb vocabulary:
  `List*`, `Get*`, `Query*`, `Sync*`, `Approve*`, `Reject*`, `Resolve*`, `Render`,
  `Apply*`, `Rollback*`, `Promote*`, `Abort*`, `Retry*`, `Skip*`, `Cancel*`,
  `Stream*`, `Investigate`.
  **Choose new verbs deliberately — the verb drives auth + audit behaviour (§7).**
- Enums: value names prefixed with the SCREAMING_SNAKE of the enum name, zero value is
  `<PREFIX>_UNSPECIFIED = 0`. e.g.
  ```proto
  enum FleetConnectionState {
    FLEET_CONNECTION_STATE_UNSPECIFIED = 0;
    FLEET_CONNECTION_STATE_HEALTHY = 1;
    ...
  }
  ```
  The only exception is the legacy `Severity` enum (line 788-793: `SEVERITY_UNSPECIFIED=0;
  CRITICAL=1; WARNING=2; INFO=3;`) — do **not** copy that pattern.
- Enum-typed fields drop the redundant prefix: `FleetHealth health = 9;`,
  `FleetSyncState sync = 10;`.

### 5.4 Comments
Sparse — only 14 comment lines in the whole file. Two idioms:
- Unit annotation directly above a field: `// Seconds since Unix epoch.` (lines 17, 19,
  206, 230).
- Section separator inside a large message, e.g. inside `Application`:
  `// Source change detection`, `// Health check results`, `// Resource sync status`,
  `// Approval gates`; inside `ApplicationSource`: `// S3 source fields`.
No `//` doc comment above message/enum/rpc declarations anywhere. Keep new comments in
the same terse style; **do add unit comments for any new numeric time/metric field.**

### 5.5 Type conventions
- **Time**: three coexisting styles — prefer the newest.
  - Legacy seconds: `int64 created_at = 3;` with `// Seconds since Unix epoch.`
  - Optional seconds: `optional int64 started_at = 3;` (presence matters)
  - Newest, millisecond-suffixed: `uint64 generated_at_ms = 4` (`InvestigateResponse`),
    `int64 timestamp_ms = 4` (`LogChunk`), `int64 last_transition_unix_ms = 21`
    (`ApplicationSummary`). **Use `_unix_ms` / `_ms` for new fields.**
  - One string timestamp exists (`KubernetesEvent.last_timestamp`, `FindingEvidence.timestamp`) — avoid.
- **Counts**: legacy uses `int32` (`out_of_sync`, `replicas`); the fleet layer uses
  `uint32` for per-object counts (`drift_count`, `resource_count`, `blocked_gate_count`)
  and `uint64` for aggregate totals (`total`, `count`, `application_count`,
  `resource_weight`). Follow the fleet convention for new work.
- **Ratios / rates**: `double` (`request_rate_weight`, `effective_weight`).
- **Enums vs strings**: legacy messages use free strings for state
  (`Application.phase`, `.health`, `ResourceSync` fields, `Rollout.phase`); the fleet
  layer uses proper enums. **New work should use enums.**
- **`optional`** is used only for genuine explicit presence, 13 occurrences: mostly
  `optional string namespace = 1;` on `List*Request` (so "unset" ≠ "all namespaces"
  ambiguity is resolvable), plus `optional int64 started_at/completed_at/checked_at`
  and `optional string pipeline_name = 2` (`ListArtifactsRequest`).
  `TestSystemStatusContract` explicitly asserts
  `request.Fields().ByName("namespace").HasPresence()` — keep `optional` on new
  namespace filters.
- **`repeated`** is plain (no packed hints), always plural field name.
- **`map<string, string>`** used 8×: `headers`, `args`, `parameters`, `http_headers`,
  `policy_overrides`, `labels`, `annotations`. No other map value types.
- **`oneof`** used 3×, always as a discriminated key (`FleetFacetBucket.key`,
  `FleetMapNode.group_key`, `FleetMatrixHeader.key`) with the shape
  `oneof key { FleetObjectKey object = 2; string value = 3; }`.
- **`reserved`** — **never used.** No field numbers have been retired.
- Namespaced identity: the fleet layer has a canonical `FleetObjectKey { namespace=1; name=2; }`.
  Reuse it for new cluster/app/project references rather than inventing another pair.

## 7. House rules for adding a new RPC — the full checklist

### 7.1 Must-do (compile-breaking if skipped)
1. `proto/paprika/v1/api.proto`
   - Add `XRequest` / `XResponse` messages adjacent to each other, in the feature block.

**Gotchas for new RPC names:**
- A read-only RPC whose name does not contain `list`/`get` is classified **ActionWrite**
  (this already affects `Query*` and `Investigate`). If you add e.g. `QueryCostByCluster`,
  it will require write permission. Either name it `Get*`/`List*`, or extend `classify`.
- The keyword scan is a substring match over the *whole procedure path*, so
  `.../GetClusterCapacity` matches no keyword → falls back to `ResourceApplications`.
  Adding a `Cluster`/`Cost`/`Metrics` resource means adding to `resourceKeywords` **and**
  to the `Resource` constants + the RBAC role model in `internal/api/auth/authz.go`
  and `project_authorizer.go`.
- `defersProjectSetAuthorization(procedure)` (line 80-90) is an **explicit allow-list** of
  procedures that do their own per-object project filtering instead of an up-front
  project-set check:
  ```go
  case v1connect.PaprikaServiceQueryApplicationsProcedure,
       v1connect.PaprikaServiceQueryFleetMapProcedure,
       v1connect.PaprikaServiceQueryFleetMatrixProcedure,
       v1connect.PaprikaServiceGetSystemStatusProcedure:
  ```
  Any new fleet-wide/cross-project read (cluster list, cost rollup, event feed) almost
  certainly belongs here. Covered by `internal/api/auth/authz_project_set_test.go`.
- Namespace/project scoping is extracted by duck-typed getters — give request messages a
  `namespace` (and `project`) field if they should be scoped:
  `extractNamespace` needs `GetNamespace() string`; see `projectFromRequest`.

## 8. Recommended shape for the redesign additions

Given §6, the lowest-friction design is: **new enums (fully prefixed), new messages, new
RPCs appended at the end of the service, and no edits to the 120 locked messages.**

| Gap | Suggested new surface | Notes |
|---|---|---|
| 1 Cluster infra | `Cluster`, `ListClustersRequest/Response`, `GetClusterRequest/Response` | reuse `FleetObjectKey` for identity; reuse `FleetConnectionState` for connection state (already has HEALTHY/UNHEALTHY/DISABLED/NOT_CONFIGURED) |
| 2 Capacity/metrics | `ClusterCapacity`, `AppMetrics`, `GetClusterCapacityRequest/Response`, `GetApplicationMetricsRequest/Response` | `double` for rates/ratios, `uint64` for bytes/millicores |
| 3 Cost | `CostSummary`, `GetCostSummaryRequest/Response` | scope by `FleetObjectKey`; `double monthly_usd`; add currency field |
| 4 Source-trigger feed | `SourceEvent` + enum `SourceEventKind` (`SOURCE_EVENT_KIND_*`), `ListSourceEventsRequest/Response` with `page_size`/`cursor` | mirror `QueryApplicationsRequest` cursor style, not `page_offset` |
| 5 Rollout history | `RolloutHistoryEntry`, `ListRolloutHistoryRequest/Response` | do **not** extend `Rollout` (locked) |
| 6 Pipeline run history | `PipelineRunSummary`, `StepResources`, `ListPipelineRunsRequest/Response` | do **not** extend `Pipeline`/`Step`/`StepStatus` (locked) |
| 7 Commit metadata | `CommitInfo` + `GetRevisionInfoRequest/Response` | avoids touching `Application`/`Release` |
| 8 Ownership | `Ownership` + `GetApplicationOwnershipRequest/Response` (or batch `ListOwnership`) | tier as enum `OWNERSHIP_TIER_*` |
| 9 Drift detail | `DriftDetail`, `ListDriftDetailsRequest/Response` | do **not** extend `ResourceSync`/`GetResourceResponse`/`ResourceTreeNode` (all locked) |
| 10 Lifecycle vector | enum `LifecyclePhase` (`LIFECYCLE_PHASE_SOURCE/BUILD/TEST/RENDER/DEPLOY/VERIFY`) + `LifecyclePhaseStatus` + `GetApplicationLifecycleRequest/Response` | |
| 11 Mutations | `HoldRollout`, `IgnoreDriftedField`, `ApplyResourcePatch`, `SyncResources` | see §7.5 — add audit verbs; see §7.4 — these classify as ActionWrite already |

Timestamps: `int64 <name>_unix_ms`. Counts: `uint32` per-object / `uint64` aggregate.
Pagination: `uint32 page_size` + `string cursor` / `string next_cursor` (fleet style),
not the older `int32 page_size` + `int32 page_offset` of `ListReleasesRequest`.
